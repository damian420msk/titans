# Броски титанов · ART-003-ABC

TypeScript + Babylon.js + Vite; Node.js + Colyseus. Сохранена локальная тренировка с неподвижной тестовой целью. Добавлена приватная дуэль двух настоящих клиентов. Оба персонажа и каменная груда — временные процедурные заглушки. Полного матча, сердец и победителя пока нет.

Из корня `C:\Users\Balan\GameDev\Titans`, в cmd:

```bat
npm ci
npm run dev
```

`dev` запускает клиент 0.0.0.0:5173 и сервер 0.0.0.0:2567. Открыть http://localhost:5173 на компьютере. На телефоне в той же Wi-Fi сети: http://192.168.1.16:5173 (текущий адрес компьютера; при его смене посмотреть `ipconfig`). HTTP/WebSocket идут через Vite `/net`, поэтому телефон использует hostname открытой страницы. Если Windows запросит доступ, разрешить частную локальную сеть. VPN/гостевая Wi-Fi сеть могут препятствовать соединению. Порты роутера, публичный туннель и отключение брандмауэра не нужны.

Кнопка «Тренировка ▾» → «Создать комнату». Передать показанный код второму игроку: он открывает тот же адрес, выбирает подключение, вводит код с сохранением регистра. Оба нажимают «Готов». После трёх секунд начинается дуэль. В комнате только два места. Закрыть меню до начала можно кнопкой «Закрыть». «Локальная тренировка» выходит из комнаты и возвращает тренировочную сцену.

Сервер авторитетен: 30 фиксированных шагов/с, отправка состояния 20 раз/с. У клиента предсказание только перемещения с подтверждением последовательности, у соперника визуальное сглаживание. Прицел до выпуска остаётся локальным. Первый обрыв транспорта даёт общую паузу до 10 секунд и отсчёт после возврата. Повторный обрыв того же игрока или невозврат завершает тестовую дуэль. Поворот/меню/фон одного клиента отменяют его ввод, общий раунд продолжается. В локальной тренировке портрет сохраняет паузу.

Остановка: Ctrl+C в терминале сервера. Если cmd предложит завершить пакетное задание — Y. В PowerShell с заблокированным npm.ps1 использовать `npm.cmd ci`, `npm.cmd run dev`, `npm.cmd run build`, `npm.cmd run check`; менять ExecutionPolicy не требуется.

```bat
npm run build
npx playwright install chromium
npm run check
```

`build` проверяет TypeScript клиента/shared/сервера и создаёт клиентский dist. Сервер запускается Node.js 24 непосредственно из TypeScript (strip-types), без второго набора боевых правил. `check` запускает TypeScript, 16 проверок Node (9 общих + 7 сетевых/двусторонних) и 30 сценариев Playwright в настоящем Chromium с WebGL. Сетевые тесты поднимают отдельные процессы на 2568–2570, проверка отключённого сервера использует Vite 5175; эти порты должны быть свободны. Playwright использует работающий dev-сервер 5173 либо временно запускает собственный. Скриншоты — reports/screenshots, запись дуэли — reports/recordings/net001-duel.webm. Первый запуск требует браузер Playwright (команда выше). Используется software WebGL; физический GPU, телефон и Safari проверяются отдельно.

Раздельный запуск в двух терминалах: `npm run dev:server` и `npm run dev:client`. Остановка каждого — Ctrl+C. `TITANS_SERVER_PORT` меняет порт сервера и цель прокси; `TITANS_TICK_RATE` (15–60), `TITANS_SNAPSHOT_RATE` (5–60) задают частоты. Значения по умолчанию 2567 / 30 / 20. Устанавливать переменные до запуска обоих процессов. Для другого явно заданного сервера доступна `VITE_SERVER_URL` (HTTP(S) адрес Colyseus); обычно она не нужна. `TITANS_TEST_LATENCY_MS` — искусственный RTT только для испытаний, по умолчанию 0. Конфигурация читается из окружения процесса; пример: PowerShell `$env:TITANS_TICK_RATE='30'`, cmd `set TITANS_TICK_RATE=30`.

Настройки ввода: «Авто / Мышь и клавиатура / Касания». Ручной выбор сохраняется в localStorage, «Авто» при перезапуске остаётся автоматическим. Изменение размера окна меняет компоновку, а не способ ввода. Режим можно менять без перезапуска раунда; при активном жесте переключение откладывается, подготовленное действие отменяется.

Компьютер: нажать кнопку входа, WASD по физическим кодам клавиш (любая раскладка), мышь без удержания — обзор, ЛКМ нажать/отпустить — обычный бросок, ПКМ — отмена, Esc — освободить курсор. Входной клик не стреляет. После Esc нужен явный повторный вход. Если захват недоступен, работает запасной обзор Alt + перетаскивание (также средняя кнопка); его можно включить кнопкой «Без захвата мыши». Перетаскивание в этом режиме не запускает действие.

Касания: только горизонтальная игровая область. По умолчанию «Свободные зоны»: касание любой свободной точки левой половины создаёт плавающий стик движения, который виден только во время использования. Правая половина даёт относительный обзор: неподвижный палец не вращает камеру. Роль пальца фиксируется при начале, пересечение середины её не меняет. Кнопки, меню и интерактивный HUD исключены из зон. При первом использовании кратко показывается подсказка. В ⚙ → «Касания» доступны «Свободные зоны / Джойстики»; выбор сохраняется. «Джойстики» сохраняют прежние постоянные круги, правый задаёт скорость обзора с мёртвой зоной 12%. Оба пальца работают одновременно, чувствительность задаётся в меню.

Небольшая кнопка справа начинает основное действие только отдельным нажатием. Удерживать, немного двигать палец для относительной коррекции прицела, отпустить для обычного броска. Выход за границу кнопки сам по себе действие не завершает. Во время подготовки в свободных зонах появляется отдельная небольшая область отмены внизу справа. Перевод туда того же пальца отменяет подготовку без расхода, переустанавливает нейтраль и сразу продолжает относительный обзор без отрыва пальца. Остальная правая половина позволяет корректировать прицел без отмены. В альтернативе «Джойстики» сохраняется прежний переход в правый круг. Возврат вверх не возобновляет атаку. Для нового броска нужно отпустить и отдельно нажать кнопку. Пополнение у арсенала использует ту же кнопку; переход к обзору его отменяет. Ловли пока нет, её будущий мобильный ввод требует отдельного решения. Прыжка и ускорения нет.

В портрете показывается полный экран поворота, ввод отменяется, локальная симуляция приостанавливается с сохранением раунда. После изменения доступной области рендер и зоны управления пересчитываются. Старые касания после поворота не стреляют. Полный экран предлагается явной кнопкой; отказ API не мешает горизонтальной игре. Узкое окно компьютера само по себе не включает касания.

Минимальный цикл: прицел выбирает целую клетку соперника, вне поля цели нет. Отпускание фиксирует клетку и расходует один камень; полёт 1,4 с, дуга 6 м над хордой, пауза между бросками 1,1 с. Удержание всегда готовит только обычный бросок — уровней заряда нет. Два попадания в обычную клетку дают трещину и отверстие; P и R сохраняют пол. При разрушении клетки под тестовой целью она падает. Падение любого участника завершает раунд: снаряды удаляются, затем оба поля, позиции и боезапас восстанавливаются. Сердец и победителя нет.

Пополнение: подойти к собственной груде с наведением на неё либо встать на P, остановиться и удерживать основное действие. Радиус 3,4 м до ближайшей точки квадрата R, один камень за 0,7 с, вместимость 3, источник бесконечный. Движение/отмена прерывают пополнение. Отпускание после пополнения не стреляет. Чтобы проверить пополнение, потратить три камня на разные клетки, не разрушая опору цели, и вернуться к своему тыловому арсеналу.

Камера: «Базовая · 70°» сохраняет исходные 5 м / 3,2 м / 70°. «Ближе · 62°» остаётся доступной для сравнения. Во время подготовки мобильного броска камера плавно переходит за 0,2 с к отступу 6 м, высоте 4,4 м, FOV 62° и прицелу на 30% высоты. При отпускании/отмене плавно возвращается. При изменении кадрирования допустимая мировая точка под прицелом сохраняется, поэтому одна анимация не переключает выбранную клетку. Автовозврата направления после отпускания джойстика нет. Геометрия поля и параметры полёта не менялись. Настройки скрыты в меню ⚙; на ПК открыть после Esc.

Качество в меню: «Авто» — до 1,5 пикселя framebuffer на CSS-пиксель и до 1,8 млн пикселей всего; «Чётче» — до 2 и 3 млн; «Быстрее» — до 1 и 0,8 млн. DPR устройства — дополнительный верхний предел. Это ограничение разрешения, не измерение FPS и не автоматический подбор по мощности устройства. При 844 × 390 и DPR 2/3: Авто 1266 × 585, Чётче 1688 × 780, Быстрее 844 × 390. На больших viewport действует общий лимит пикселей. Настройка сохраняется.

Диагностика выключена по умолчанию: ⚙ → «Диагностика экрана и прицела». Показывает visual viewport, canvas rect, framebuffer, DPR, scaling, координаты DOM-прицела и луча, точку пересечения, выбранные индексы и интервал кадра. Подписи координат над полем убраны. Интервал кадра не является измерением времени GPU.

Исходные правила: docs/concept/titans_concept_v01.
